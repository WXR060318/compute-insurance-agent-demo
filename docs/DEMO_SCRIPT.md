# 三分钟演示脚本

本系统中的企业、供应商、报价、库存与质量分数均为模拟数据。开场说明一次，界面保留演示标识。

## 开演前

启动系统，选择星河模型、需求激增、13:30。清除预算上限，质量门槛98，按成本排序。准备一个正常场景、一个供应不足场景作为反例。若使用真实模型，提前完成本机连通测试；否则保留清晰的离线规则模式。

## 演示过程

0:00—0:30：企业当前有8张同规格GPU。需求趋势与计划任务显示，14:00后需要12张，因此提前形成4张的缺口预警。这里展示预计资源缺口及依据。

0:30—1:00：拖动或推进回放时间，观察当前需求、预警提前量和剩余采购量变化。切回13:30，展示完整两小时、8卡时的预计缺口。

1:00—1:40：进入资源调度。供应商A能按时提供4张，采购成本为4×2×12＝96元；B便宜但交付太晚；C只有2张，单独无法完整覆盖。说明先检查兼容与交付条件，再比较成本和质量。

1:40—2:15：在智能体助手中询问“为什么不选更便宜的B？”，展示工具执行记录与依据。再问“预算只有80元”，查看无法完整匹配的结果和剩余缺口。

2:15—2:45：恢复预算，生成处置预案，人工模拟确认并导出处置单。说明这些记录可以复核计算时的数据与规则；模拟确认不代表真实采购或锁定资源。

2:45—3:00：切到供应不足或数据失效场景，说明系统会保留未解决状态。指出保险服务和给付条件的待确认事项，结束演示。

## 常见追问

预测如何得出：首版采用当前可见的历史趋势和计划任务作演示基线。规则与输入可复核，尚未通过真实业务数据验证预测准确率。

为什么看GPU型号：不同规格和工作负载不可直接按卡数等价相加；首版限定同规格资源。

能否一定找到算力：候选供应不足时保留缺口，平台匹配能力取决于可核验的外部供给。

96元是否为保险赔款：它是模拟资源采购成本。保险是否承担、如何承担，取决于团队后续明确的条款和服务规则。
